1NAMU가 뭐예요?

한 문장으로: "AI는 갈아끼워도, 기억은 내가 들고 다니는 시스템"

NAMU(나무)는 클로드·제미나이·GPT 같은 여러 AI를 부려서 일을 시키되, 그 과정에서 얻은 경험과 교훈을 한 곳에 차곡차곡 쌓아두는 개인용 AI 작업 시스템이에요. 핵심은 "어떤 AI를 쓰느냐"가 아니라 "그 기억을 누가 가지고 있느냐"예요.

💡 쉬운 비유

보통 AI 챗봇은 그 회사 앱을 나가면 대화 내용을 다 잊어버려요. 마치 매번 처음 만나는 직원 같죠. NAMU는 그 직원이 바뀌어도 똑같이 보는 공용 업무 노트를 내가 직접 들고 있는 구조예요. 직원(AI)은 바뀌어도 노트(기억)는 그대로라서, 새 직원도 노트만 읽으면 바로 일을 이어받아요.

"독립성은 화면(인터페이스)이 아니라
기억(메모리)에 있다"
이게 NAMU 프로젝트 전체를 관통하는 가장 중요한 깨달음이에요

그래서 기억은 내 파일로 남아요. 특정 회사 서버 안에 갇히지 않고, AI를 바꿔도 그대로 따라와요. 다른 AI의 기억 기능과 갈라지는 지점도 여기예요 — 나무는 결과만이 아니라 왜 그렇게 했는지를 함께 남깁니다.

2왜 만들어요? — 기획 의도

세 가지 바람에서 출발했어요

🔓

① AI에 안 묶이기

클로드가 막히면 제미나이로, 그것도 안 되면 내 PC의 무료 모델로. 한 회사 정책·요금·서비스 종료에 휘둘리지 않아요.

🧠

② 기억 공유하기

모든 AI가 같은 노트를 봐요. 게다가 노트북·집 PC 어디서 작업해도 같은 기억이 따라다녀요.

📈

③ 스스로 발전하기

성공·실패만이 아니라 "왜 그렇게 판단했는지 이유"까지 쌓아요. 이게 쌓이면 시스템이 스스로 기준을 만들어가요.

🌍

④ (먼 미래) 함께 크기

나중엔 일반적인 교훈을 커뮤니티 공용 풀에 선택적으로 나눠서, 쓸수록 모두가 똑똑해지는 구조도 꿈꿔요. 지금 쌓이는 기억은 전부 개인 것이에요.

"이유까지 기록한다"가 왜 중요할까?

그냥 "성공/실패"만 적으면, 나중에 패턴을 분석할 때 엉뚱한 기준을 뽑아낼 수 있어요. 예를 들어 "금요일에 한 작업은 다 실패했네 → 금요일을 피하자" 같은 헛다리요. 하지만 왜 실패했는지(이유)가 같이 적혀 있으면 "아, 테스트를 안 돌려서 실패한 거구나"라는 진짜 원인을 잡을 수 있어요.

🧱 그래서 기억 한 건은 반드시 3층으로 남아요
무엇을(summary) · 왜(reason) · 그때 무슨 일이(body) — 세 층이 전부 필수예요. 정말 적을 게 없을 때만 생략 한 단어를 넣어 넘어갈 수 있고, 그냥 빈칸으로는 저장이 거부돼요. 예전엔 그릇마다 입력 칸이 제각각(19개)이었는데, 모든 그릇 공통 3층 · 칸 13개로 통일했어요.

3어떻게 만들어요? — 설계

"다 직접 만들면 끝이 없다" → 빌릴 건 빌리고, 핵심만 직접 만들어요

처음엔 모든 걸 직접 만들려다가, 중요한 결정을 했어요. AI 작업 시스템을 3개 층으로 나눠서, 이미 잘 만들어진 부분은 가져다 쓰고 진짜 핵심인 기억 부분만 직접 만들기로요.

A

실행 엔진

AI를 호출하고, 파일을 고치고, 명령어를 돌리는 부분. (예: Claude Code, agy=안티그래비티)

빌려쓴다
B

작업 절차

"작업 전엔 꼭 기억을 확인해라" 같은 규칙·자동화·작업 순서. NAMU가 직접 만들어요.

직접 제작
C

메모리 / 학습 코어 💚

경험을 쌓고 꺼내쓰는 부분. 이게 NAMU의 심장이자 진짜 차별점이에요.

직접 제작
왜 이렇게 나눴나요? 실행 엔진(A)은 큰 회사들이 수년간 다듬은 부분이라 직접 만들면 시간 낭비예요. 반면 "기억과 학습"(C)은 어디서도 안 주는, NAMU만의 가치라서 여기에 힘을 집중해요. 그래서 실행 엔진은 언제든 갈아끼울 수 있는 부품으로 취급해요.

핵심 코어(C층)는 'MCP 서버'라는 형태로

기억 코어를 MCP 서버라는 형태로 만들었어요. MCP는 쉽게 말해 "AI에 갖다 붙이는 표준 콘센트"예요. 이 콘센트 규격으로 만들어두면 클로드든, 다른 AI 도구든 똑같이 꽂아서 같은 기억을 쓸 수 있어요. 바로 이 점이 "AI에 안 묶인다"는 목표를 진짜로 실현해줘요.

4무엇을 기억하나 — 다섯 그릇

성격이 다른 기억을 한 통에 담으면 나중에 아무것도 못 찾아요. 그래서 다섯 그릇에 나눠 담아요

📚

교훈 learnings

다시 쓸 배움. "이 방식은 이래서 실패했다", "이 설계를 고른 이유는 이것이다" 같은 것.

👤

개인 사실 profile

나에 대한 사실. 쓰는 기기, 일하는 방식, AI에게 바라는 것.

📋

작업일지 tasks

진행 기록. 무슨 작업이 열려 있고 어디까지 했는지, 다음엔 뭘 할지.

🗒️

쪽지 memo

쓰고 버리는 메모. 다섯 중 유일하게 뗄 수 있어요 — "영화 8시 20분" 같은 한 번 쓰고 마는 것의 자리.

📎

첨부 기록 attachments

올린 파일의 이력만. 파일 몸통은 여기 없고 내 저장소에 있어요.

🧱

모든 그릇 공통 — 3층

어느 그릇에 담든 무엇을 · 왜 · 그때 무슨 일이 세 층으로 남아요. 그릇을 안 고르면 저장 자체가 거부돼요.

왜 쪽지 그릇을 따로 팠나요? "영화 8시 20분" 같은 일회성 메모가 갈 곳이 없어서 교훈 노트로 밀려들어오던 게 문제였어요. 지식베이스가 잡동사니로 오염되면 검색 품질이 떨어져요. 그래서 떼면 사라지는 그릇을 따로 만들었어요 — 지식베이스 오염 0이 이 그릇의 존재 이유예요.

순서가 핵심이에요. 원본에 먼저 쓰고, 검색용 사본은 그다음. 사본이 깨져도 원본만 멀쩡하면 전부 되살릴 수 있으니까요. 이 순서는 절대 안 바꿔요. 언제나 기준이 되는 건 원본 쪽이에요.

검색용 사본은 다섯 그릇을 전부 담아요. 예전엔 교훈 하나만 넣고 나머지는 찾을 때마다 파일을 통째로 읽었는데, 그릇마다 찾는 방식이 달라 한쪽만 좋아지는 일이 생겨서 하나로 모았어요(2026-08-08). 그릇마다 원본이 바뀌었는지 먼저 보고, 바뀐 그릇만 다시 만들어요.

한글 검색은 이렇게 돌아가요. 띄어 쓴 낱말이 전부 들어 있는 것만 걸려요(순서는 상관없어요). 다만 두 글자짜리 낱말이 섞이면 검색용 사본을 건너뛰고 원본을 처음부터 훑어요 — 사본이 trigram(세 글자 단위)으로 만들어져 있어 두 글자로는 원리상 못 찾기 때문이에요. 결과는 같고 조금 느릴 뿐이에요.

어디에 저장되나 — 내 컴퓨터 안 폴더 하나(~/.namu)

전부 내 컴퓨터 안의 폴더 하나에 모여요. AI 회사 서버가 아니에요. 이 경로는 어디서 실행하든 항상 같아요 — 예전에 있던 "개발 모드 / 설치 모드" 구분은 아예 없앴어요.

~/.namu/ ← 내 컴퓨터 안의 평범한 폴더. 열어서 눈으로 읽을 수 있어요 ├─ memory/ │ ├─ learnings.yaml 📚 교훈 — 프로젝트 안 가리고 한 칸에 다 섞임 │ ├─ profile.yaml 👤 개인 사실 │ ├─ memo.yaml 🗒️ 쪽지 — 떼면 사라지는 유일한 칸 │ └─ attachments.yaml 📎 첨부 기록 — 이력만, 파일 몸통은 여기 없음 ├─ tasks/ │ ├─ 내프로젝트-가/ 📋 작업일지 — 프로젝트마다 칸이 따로 │ │ ├─ task.md 목적·완료조건 (거의 안 바뀜) │ │ ├─ log.md 시간순 기록 (덧붙이기만) ← 권위 기록 │ │ └─ .pin.<기기> 📌 책갈피 — "다음엔 이것부터" │ └─ 내프로젝트-나/ 다른 프로젝트는 다른 칸 └─ db/ └─ namu.db 🔍 검색용 사본 — 지워도 원본에서 다시 만들어짐
💡 쉬운 비유

전부 내 중앙 서랍장(~/.namu)에 살아요. 다만 일반 상식(교훈)은 프로젝트를 안 가리고 한 칸에 다 섞어 모아두고(어디서든 꺼내 쓰려고), 이번 프로젝트 메모(작업일지)는 같은 서랍장 안에서 프로젝트별 칸으로 나눠 넣어둬요. 작업일지를 프로젝트 폴더가 아니라 여기 두는 이유는 두 가지예요 — 프로젝트 폴더는 남에게 공개될 수 있고, 여러 PC 사이 자동 맞춤에 같이 얹기 위해서요.

작업을 닫는 말은 딱 둘이에요 — [완료]·[중단]. [종료]·[마무리] 같은 비슷한 말은 저장은 되지만 작업을 닫지 못해서 조용히 열린 채로 남아요. 실제로 그런 사고가 나서, 지금은 그런 말로 닫으려 하면 기록 자체를 거절해요.

9사용법 — 아주 쉽게

먼저 나에게 맞는 길부터 고르고, 그다음 설치예요

🧭 나에게 맞는 것 고르기

1

검은 화면(터미널)에서 AI를 쓰시나요?

예 → 플러그인을 설치하세요. 거기에 기억 동기화까지 켜면 권장 구성이 완성돼요 — 나무의 모든 기능이 켜집니다.
아니오 → 다음 질문으로.

2

서버를 직접 운영할 생각이 있으신가요?

아니오, 그냥 쓰고 싶다 → 나무 클라우드에서 주소를 받으세요. GitHub 계정만 있으면 되고, 설치도 카드 등록도 없어요.
예, 내 손으로 운영하겠다 → 직접 서버를 운영해 주소를 만드세요.

3

나무 자체를 고쳐보고 싶으신가요?

→ 개발형. 저장소를 통째로 내려받아 그 안에서 실행하면 코드를 고치는 즉시 반영돼요. 되는 일은 보통 설치와 같아요.

📦 ① 플러그인 설치 — 명령 두 줄

# Claude Code에서 실행
claude plugin marketplace add onmiso-hash/namu-agent
claude plugin install namu@namu-marketplace
참고: NAMU repo는 공개(public) 저장소예요. 별도로 초대받거나 git 자격증명을 미리 준비할 필요 없이, 누구나 위 두 줄만으로 바로 설치할 수 있어요.

설치 확인 — Claude Code에서 /mcp를 치면 plugin:namu:namu-memory ✔ connected가 보여야 정상이에요.

첫 세션은 조용한 게 정상이에요. 설치 직후엔 보여줄 기억(쪽지·교훈·진행 중 작업)이 아직 하나도 없어서 브리핑이 안 떠요. 실패가 아니라 기억이 쌓인 뒤 다음 세션부터 브리핑이 시작되는 거예요.

기기 이름(NAMU_MACHINE)은 설정 안 해도 컴퓨터 호스트명으로 자동 인식돼요. 여러 PC를 쓸 때 라벨을 예쁘게 고정하고 싶을 때만 정해주면 돼요.

📘 자세한 설치·문제해결은 설치 가이드에서
로컬 경로 설치, agy(안티그래비티) 설치, 업데이트·삭제 절차, 트러블슈팅까지는 이 안내서 범위를 넘어요. → 설치 가이드 보러 가기 · 복붙만으로 끝내려면 → 빠른 시작

🔄 ② 여러 PC에서 같은 기억 쓰기 — 동기화 켜기

기억은 내 컴퓨터 안 폴더에 쌓여요. 그대로 두면 그 컴퓨터에만 남아요. 회사 노트북에서 하던 일을 집 PC에서 이어받으려면 동기화를 한 번 켜두세요.

남길 때마다 저절로 올라감

🏠 집 PC

🔄 동기화 켜는 법
① GitHub에 빈 비공개 저장소를 하나 만들고(README 없이, 비공개도 무료예요. 이름은 자유지만 namu-memory를 많이 써요), 그 컴퓨터에서 git 로그인(gh auth login 등)까지 해둬요 — 여기까지가 내 몫이에요 → ② AI에게 "기억 동기화를 이 주소로 켜 줘"라고 한 번만 부탁하면 끝 → ③ 그다음부턴 기억을 남길 때마다 자동 백업, 새 대화를 열 때마다 자동 수신 → ④ 두 번째 PC에서도 같은 말 한 번이면 기존 기억과 자동으로 합쳐져요(따로 병합 작업 필요 없음).

저장소 만들기가 귀찮으면 — 나무 클라우드에 GitHub로 로그인하면 이름과 비공개가 미리 채워진 생성 화면으로 안내해줘요. 만들기 버튼 한 번만 누르면 돼요.

💻

설치형 — 대부분의 사용자

그냥 내 프로젝트에서 Claude Code를 열면 돼요. 브리핑이 자동으로 뜨고, /namu-task로 작업을 진행하고, 남길 만한 게 생기면 AI가 판단해 기록해요(이유 필수). 기억은 ~/.namu에 자동 저장되니 따로 pull·push할 필요가 없어요.

🛠️

개발형 — 나무 저장소 자체를 개발할 때만

나무 코드를 고치는 개발자라면 그 repo는 받아오기 → 작업 → 올리기로 코드를 관리해요. 하지만 기억 저장 위치는 설치형과 똑같이 ~/.namu예요(저장소 안이 아니에요). 예전의 "개발 모드/설치 모드" 구분은 폐지됐어요.

🌐

주소형 — 웹 브라우저에서만

설치도 프로그램 실행도 없이 웹의 claude.ai에서만 쓰는 형태예요. 다섯 그릇을 그대로 읽고 쓰고 파일도 주고받지만, 브리핑·/namu-task·일꾼 AI 같은 절차는 안 따라와요(6장 표 참고).

💡 저장 위치, 한 줄 정리

플러그인으로 쓰면 전부 내 컴퓨터 ~/.namu에, 나무 클라우드로 쓰면 내 GitHub 비공개 저장소에 담겨요. 어느 쪽이든 기억 원본은 계속 내 것이고, AI 회사 서버에 갇히지 않아요.

기억 도구를 직접 써보고 싶다면? 도구 이름을 외울 필요는 없어요 — 그냥 말로 하면 AI가 알아서 골라 써요.
· 꺼내기: "지난번에 정한 거 뭐였지?" → 브리핑·namu_recall
· 찾기: "SQLite 관련해서 배운 거 있어?" → namu_search
· 남기기: "이거 교훈으로 남겨줘, 이유는 ○○" → namu_record (무엇을·왜·그때 무슨 일이 3층 필수!)
· 쪽지: "영화 8시 20분 메모해둬" → 쪽지 그릇에. 다 쓰면 "그 메모 떼줘"
· 책갈피: "다음엔 이것부터라고 꽂아둬" → 다음 브리핑 맨 위에 📌
· 파일: "이 글 파일로 올려줘" / "지난번 그 파일 다시 줘" → 첨부 도구
