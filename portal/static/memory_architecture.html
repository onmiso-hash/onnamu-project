기억은 하나, 실행 엔진은 빌려 쓴다

NAMU의 기억은 머신마다, AI마다, 그리고 기억의 종류마다 남기는 방법과 사는 곳이 다릅니다. 이 문서는 그 전체 구성을 다이어그램으로 한 장에 펼쳐, 매번 다시 묻지 않아도 되게 만든 설계도입니다.

데이터 루트 ~/.namu (고정) 진실의 원천 다섯 그릇 (yaml · md) 인터페이스 MCP · 도구 15종 (주소는 11종) 동기화 Git (선택)

02 세 개의 축

"다르게 남긴다"는 건 세 축이 겹쳐 있다는 뜻

기억이 달라지는 방향은 딱 세 가지입니다. 이 셋은 서로 직교(independent)합니다 — 하나의 기록은 세 축의 좌표를 동시에 갖습니다. 예: "hp 머신에서 · Claude Code가 · 교훈(lesson)으로" 남긴 한 줄.

Axis A · 종류

기억의 종류 (그릇)

무엇을 기억하느냐에 따라 사는 그릇이 갈립니다. 성격이 다른 기억을 한 통에 담으면 나중에 아무것도 못 찾기 때문입니다. 그릇은 생략할 수 없습니다 — 안 적으면 거절하고 그릇 목록을 안내합니다.

필드 bowl = learnings · profile · tasks · memo · attachments

어느 기기에서

PC마다 스냅샷·작업 컨텍스트는 따로 쌓이지만, 원천 풀은 Git으로 하나로 합류합니다. 저장은 분산, 진실은 통합.

필드 machine = hp · samsung · web · cloud …

어느 AI·엔진이

03 그릇 (Axis A 상세)

다섯 그릇 — 모두 같은 3층

namu_record는 도구 하나지만 bowl 파라미터로 서로 다른 그릇에 라우팅합니다. 도구 수를 늘리는 대신 라우팅으로 그릇을 나눈 설계입니다.

그릇이 다섯으로 늘면서 입력 칸도 통일됐습니다(namu-65 · v0.1.43). 그릇마다 제각각이던 19개 칸을 모든 그릇 공통 3층(무엇을 summary · 왜 reason · 그때 무슨 일이 body) 위에 얹어 13개로 줄였습니다. 세 층은 전부 필수이고, 적을 게 없으면 생략 한 단어를 넣습니다 — 빈칸은 거부됩니다.

쪽지 그릇이 왜 생겼나 (namu-56 · 구현 완료): "영화 시간표"처럼 일회성 정보를 저장하라고 하면 마땅한 그릇이 없어 learnings.yaml(지식베이스)이 오염됐습니다. 지식베이스 오염 0이 이 그릇의 존재 이유이고, 그래서 검색 색인도 교훈과 합치지 않고 자기 표를 따로 갖습니다. git 병합도 줄 단위 union이 아니라 파일 단위입니다 — union은 삭제를 표현하지 못해 뗀 쪽지가 병합 때 되살아나기 때문입니다.

i

그릇 레지스트리: 그릇의 성질은 config.py의 BOWLS에 한 번만 선언합니다. .gitattributes의 merge=union 줄이 여기서 파생되므로, 새 그릇을 등록하는 것이 곧 병합 정책을 정하는 일입니다. 하드코딩 목록을 아무도 갱신하지 않아 profile.yaml이 병합 보호 없이 방치됐던 실제 버그가 계기였습니다.

recall vs search — 같은 query, 다른 목적

  • recall = 작업 시작 전 맥락 로딩. "뭐라도 준다" — 매칭이 약하면 최신순으로 폴백. 붙여둔 쪽지·최근 활동·열린 작업·profile 전체·관련 교훈을 한 번에 돌려주고, 받아오기가 실패한 적이 있으면 warnings 키로 그 사실도 함께 옵니다.
  • search = 판단 중 패턴 분석. 정확히 매칭되는 것만, 없으면 빈 결과. 다섯 그릇 전부가 검색 대상입니다(2026-08-08 통일 — 예전에는 교훈 전용이었습니다).
  • 낱말 규칙 — 띄어 쓴 낱말이 전부 들어 있는 것만 걸립니다(순서 무관). 세 글자 미만이 섞이면 색인을 건너뛰고 LIKE로 전수 조회합니다 — trigram은 두 글자를 원리상 못 찾기 때문입니다.

Git으로 공유

PC 간 합류하는 것

learnings.yaml · profile.yaml · attachments.yaml · tasks의 task.md·log.md. .gitattributes의 merge=union + ULID 키 덕분에 오프라인 다중 PC 병합 충돌이 0. memo.yaml만 파일 단위 병합입니다 — union은 삭제를 표현하지 못해 뗀 쪽지가 되살아나기 때문입니다.

기기에만

재생성되는 캐시

db/는 gitignore 대상. namu.db는 그릇마다 원본의 크기·수정시각을 모은 서명이 어긋나면 그 그릇만 다시 만듭니다(세션 시작·서버 부팅·pull 직후). .pin.[machine]은 기기마다 파일을 갈라 git 충돌을 0으로 둔 책갈피입니다 — 각 기기는 제 파일에만 씁니다.

분류 기준

두 갈래로 나뉜 성격

개인전역지식 = memory/*.yaml (프로젝트 무관 한 풀). 프로젝트상태 = tasks/[basename(프로젝트)]/. 저장 위치는 같은 ~/.namu지만 귀속 기준이 다릅니다.

07 원격 MCP — 개인 · 공용

기억을 네트워크 너머로 여는 두 경로

stdio 로컬 서버가 기본이지만, 웹 Claude(claude.ai) 같은 원격 클라이언트를 붙이려면 HTTP로도 서빙해야 합니다. 여기에 두 갈래가 있고 둘 다 라이브입니다 — 직접 서버 운영(내가 띄움)과 나무 클라우드(나무가 대신 띄움). 되는 일은 양쪽 다 도구 11종으로 같고, 다른 것은 서버를 누가 운영하느냐와 기억 원본이 어디 남느냐뿐입니다.

두 배포 형태

① 자기 PC 상시구동 + 터널(cloudflared·pinggy)로 공개 HTTPS — 지금 쓰는 그 ~/.namu 그대로. ② 상시 서버 컨테이너 — 부팅 시 GitHub에서 clone. 인증은 토큰 헤더 또는 시크릿 경로. 받아오기(pull) 실패는 기동을 막지 않습니다 — 실패 사실만 startup_sync.json에 남아 브리핑 경고로 계속 뜹니다(2026-08-16 무한 재시작 사고 이후). clone 실패는 종전대로 치명적입니다.

나무 클라우드

신원은 개인 열쇠 (namu-59)

사람마다 다른 개인 열쇠가 주소에 실려 오면 서버가 그것으로 누구인지 판정해 user를 직접 채웁니다 — 요청에 ?user=를 손으로 실어 보내도 걷어내고 다시 씁니다. 예전의 전원 공용 시크릿 + 위조 가능한 라벨("협조적 격리")은 인증이 아니었고, 그래서 없앴습니다.

원본의 소유

서버가 갖는 건 사본뿐

기억 원본은 회원 본인의 GitHub 비공개 저장소입니다(연결할 때 직접 고름). 서버는 그 사본으로 일하고 기록을 저장소로 되돌려 보냅니다. 그만두면 주소를 폐기하면 되고, 저장소는 원래부터 회원 계정에 있어 옮길 것이 없습니다.

⚑

주소로 건너가는 것의 한계: 원격으로 여는 건 메모리 코어(레이어 C)뿐입니다. 세션 브리핑·/namu-task·워커·화면 아래 한 줄·마무리 훅(레이어 B)은 AI 프로그램에 끼워 넣는 글루라 주소로는 안 따라옵니다 — 웹이라서가 아니라 주소로 붙였기 때문이고, 터미널 AI에 주소만 붙여도 결과는 같습니다. 반면 tasks 그릇과 첨부 도구 일곱 개는 이제 노출됩니다(도구 11종). 빠지는 넷은 쪽지 떼기·책갈피 2종·sync_setup뿐입니다.

i

웹에는 "지금 열어 둔 폴더"가 없습니다. 그래서 새 작업을 만들 때 어느 방인지 부르는 쪽이 지어내지 못하게 막았습니다 — 이미 있는 방이나 web-project 중에서 골라야 하고, 안 정해졌으면 방 목록을 돌려줍니다. 확인 칸·질문·시간 문턱으로 검사하던 게이트를 두 판 만들어 두 판 다 뚫린 뒤, 검사 대신 자리 자체를 없애는 쪽으로 바꾼 결과입니다.

08 흔들리지 않는 원칙

이 설계가 지키는 여섯 가지

01

독립성은 메모리 레이어에

인터페이스가 아니라 MCP에 포터블하게. 실행 엔진은 빌려 쓰고 교체 가능한 부품.

02

원본이 곧 기억

다섯 그릇의 원본 파일이 진실의 원천. SQLite는 재생성 가능한 캐시일 뿐 — 원본 먼저 쓰고 색인은 그다음.

03

append-only 로그

learnings.yaml과 작업 log.md는 수정·삭제하지 않는다. 정정은 새 항목으로.

04

승인 게이트

워커 호출 전, 검수 fail 후 재실행 전 반드시 사용자 확인. 자동 재실행 금지.

05

판단 이유 기록

결과만이 아니라 무엇을·왜·그때 무슨 일이 3층 전부. 빈칸이면 ValueError로 차단(생략은 허용).

06

데이터 루트 고정

~/.namu 고정 상수 — 환경변수로도 못 바꿈. 분기가 없으니 오배선도 불가능.
