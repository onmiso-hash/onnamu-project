나무 클라우드 — 주소만 받아서 쓰기

서버를 직접 띄우지 않고도, 나무가 대신 운영하는 공용 기억 서버에서 나만의 접속 주소 하나를 받아 웹 브라우저의 claude.ai 같은 AI에 붙이면 바로 기억을 꺼내 쓰고 남길 수 있습니다. 기억 원본은 여러분 GitHub의 비공개 저장소에 남습니다.

🔑 주소로는 도구 11개 🍱 다섯 그릇 전부 🔐 사람마다 다른 개인 열쇠 📅 기준일 2026-08-29 · 나무 v0.1.73
🌳 처음 오셨다면 이 문서가 아니라 namu-cloud.onnamu.kr로 가세요. 가입 절차는 사이트 화면이 직접 안내하고, 궁금한 것은 사이트의 AI 안내원에게 바로 물어볼 수 있습니다. 이 문서는 그 뒤에 "안에서 어떻게 도는가"를 알고 싶은 분을 위한 것입니다.

1 이게 뭔가 — 직접 운영과 차이

되는 일은 양쪽이 똑같습니다. 다른 것은 누가 서버를 운영하느냐와 기억 원본이 어디에 남느냐, 이 둘뿐입니다.

직접 서버 운영나무 클라우드 (이 문서)
서버는 누가 띄우나내가 직접나무 쪽에서 대신
기억 원본은 어디에내 PC 안 ~/.namu내 GitHub 비공개 저장소 — 연결할 때 직접 고릅니다. 서버가 갖는 것은 그 저장소의 사본뿐입니다
사용자 수단일 사용자(자기 것 하나)여러 사람 — 주소에 실린 개인 열쇠로 사람마다 서랍이 갈립니다
준비물상시 켜둘 PC·서버 + 밖에서 접속할 주소GitHub 계정

돈서버 비용은 내 몫무료 · 카드 등록 없음
💡인프라 세부(포트·이미지 태그·Cloudflare ingress)는 onnamu-project에서 관리하므로 이 문서에서는 다루지 않습니다 — 같은 것을 두 곳에서 관리하면 한쪽만 낡습니다.

2 되는 것 / 안 되는 것

주소로 건너가는 것은 기억과 파일입니다. 나무의 나머지 절반인 작업 절차는 플러그인에만 들어 있어 주소로는 따라오지 않습니다.

✅ 되는 것 — 도구 11개

기억 4가지 — namu_recall(꺼내기) · namu_search(찾기) · namu_record(남기기) · namu_task_move(작업을 다른 방으로 옮기기).

파일 7가지 — namu_upload_file · namu_list_files · namu_download_file · namu_delete_file, 그리고 주고받는 링크 3종(namu_create_upload_ticket · namu_create_download_ticket · namu_check_ticket).

담을 수 있는 그릇은 다섯 전부입니다 — 교훈(learnings)·개인 사실(profile)·작업일지(tasks)·쪽지(memo)·첨부 기록(attachments). 기록은 개인용과 같은 3층(무엇을 summary · 왜 reason · 그때 무슨 일이 body)으로 남습니다.

❌ 안 되는 것

기능왜 없나요
세션 브리핑 · /namu-task · 일꾼 AI · 화면 아래 한 줄 · 마무리 붙잡기 전부 AI 프로그램 자체에 끼워 넣는 작업 절차라 주소로는 따라오지 않습니다. 웹이라서 모자란 것이 아니라 주소로 붙였기 때문이며, 터미널 AI에 주소만 붙여도 결과는 똑같습니다. 이쪽까지 원하시면 플러그인 설치 쪽입니다.
namu_sync_setup 서버의 저장소 연결(git remote)을 통째로 바꾸는 도구입니다. 원격에 열어두면 남의 저장소로 연결을 갈아끼워 기억을 통째로 빼앗을 수 있어 원천 차단합니다.
쪽지 떼기(namu_memo_remove) · 책갈피 꽂기·빼기(namu_task_pin/namu_task_unpin) 그 PC의 파일을 직접 다루는 도구입니다. 쪽지를 붙이는 것은 여기서도 되고, 떼는 것만 그 PC 몫입니다.
새 프로젝트 방 만들기 안 되는 게 아니라 일부러 막았습니다. 웹에는 "지금 열어 둔 폴더"가 없어서, 예전에는 AI가 프로젝트 이름을 지어내 엉뚱한 방이 늘어났습니다. 지금은 이미 있는 방이나 web-project 중에서 골라야 하고, 안 정해졌으면 방 목록을 돌려줍니다. 잘못 들어간 작업은 namu_task_move로 옮깁니다.

노출 기준은 직접 서버 운영과 같습니다 — 그쪽 1절과 같은 목록입니다.

3 연결법 — 주소 받아 붙이기

절차의 원본은 사이트 화면 자체입니다. 여기에 같은 절차를 다시 적으면 화면을 고칠 때 한쪽만 고쳐지므로, 이 문서는 사이트를 가리키기만 합니다.

1

namu-cloud.onnamu.kr에서 시작합니다

화면이 시키는 대로 따라가면 로그인 → 저장소 마련 → 권한 → 접속 주소까지 끝납니다. 저장소는 이름(namu-memory)과 비공개가 미리 채워진 생성 화면으로 안내하므로 만들기 버튼 한 번이면 됩니다.

2

받은 주소를 AI에 붙입니다

claude.ai라면 설정(Settings) → 커넥터(Connectors) → 사용자 정의 커넥터 추가에 주소를 통째로 붙여넣고 저장합니다. 창을 닫았어도 내 페이지에서 주소를 다시 볼 수 있습니다.

주소 형식

https://namu-cloud.onnamu.kr/mcp/<내-개인-열쇠>?client=<AI-이름>
  • <내-개인-열쇠> — 사람마다 다른 무작위 값입니다. 위 절차로 자동 발급되며, 운영자가 나눠주는 공용 값이 아닙니다.
  • ?client= — 이 기억을 남긴 AI가 누구인지 나타내는 출처 태그입니다(4절). 다른 웹 AI를 쓴다면 client=claude를 그 AI 이름으로 바꿔서 붙입니다.
⚠이 주소는 사실상 비밀번호입니다. 아는 사람은 여러분의 기억을 읽고 쓸 수 있습니다 — 채팅·이슈·스크린샷에 그대로 붙여넣지 마세요. 새어 나갔다면 내 페이지에서 재발급하면 옛 주소는 즉시 막힙니다.
⚠터미널 AI(Claude Code·agy)에는 이 주소를 붙이지 마세요. 주소로는 기억과 파일만 건너가고 작업 절차는 안 따라오는 데다, 기억이 쌓이는 자리도 갈라집니다(플러그인은 그 PC의 ~/.namu, 이 주소는 내 GitHub 저장소). 반쪽짜리를 쓰면서 기억까지 두 곳으로 흩어지는 셈입니다 — 터미널이라면 플러그인 설치 쪽입니다.

4 client가 뭔가

이 기억을 남긴 AI가 누구인지 나타내는 출처 태그입니다(내부적으로는 via로 저장). 기록할 때 함께 저장돼, 나중에 "claude가 남긴 이력만" 같은 출처별 조회의 기준이 됩니다.

값형식
client영숫자 · . · _ · - 1~40자 (^[A-Za-z0-9._-]{1,40}$)
⚠노출된 도구 열한 개 전부 client가 필수입니다 — 없거나 형식이 틀리면 도구 호출이 한국어+영어 상세 에러로 거부됩니다. 주소 끝에 ?client=<AI 이름>을 붙여 다시 등록하면 됩니다.
💡정확한 모델명(claude / chatgpt / gemini / cursor / copilot)을 그대로 넣기를 권합니다. 애칭·변형도 형식만 맞으면 거부되지 않지만, 나중에 조회할 때 저장했던 값과 글자 그대로 똑같이 넣어야 찾힙니다 — claude와 cld는 서로 다른 값으로 저장됩니다.
✓user는 이제 사용자가 붙이지 않습니다. 예전에는 ?user=<내 키>로 서랍 이름표를 직접 적어 보냈지만, 지금은 서버가 주소에 실린 개인 열쇠로 누구인지 판정해 직접 채워 넣습니다. 요청에 ?user=를 손으로 실어 보내도 서버가 걷어내고 다시 씁니다 — 남의 이름표를 적어 넣어 남의 서랍을 여는 수법을 없애기 위한 구조입니다.

5 인증·격리 — 개인 열쇠

사람마다 다른 개인 열쇠가 곧 신원입니다. 열쇠가 주소에 실려 오면 서버가 그것으로 누구인지 판정하고, 그 사람의 서랍으로만 길을 냅니다.

기억 원본은 서버가 아니라 내 저장소에

연결할 때 고른 여러분 GitHub의 비공개 저장소가 원본입니다. 서버가 갖는 것은 그 저장소의 사본이고, 기억을 남기면 서버가 여러분 저장소로 되돌려 보냅니다. 그래서 서비스를 그만두어도 기억은 원래부터 여러분 계정에 있으니 옮기거나 내려받을 것이 없습니다.

주소가 새면

내 페이지에서 재발급하면 옛 주소는 즉시 막힙니다. 열쇠가 곧 신원이라, 열쇠를 바꾸는 것이 곧 자물쇠를 바꾸는 것입니다.

🔐옛 판의 "협조적 격리"는 끝났습니다. 최초에는 전원이 같은 공유 시크릿을 쓰고 ?user=로 서랍을 가리키는 방식이었습니다. 그건 인증이 아니었습니다 — 공유 시크릿을 아는 사람이 남의 키만 알아내면 그 서랍도 열렸습니다. 지금은 사람마다 다른 개인 열쇠로 바뀌었고, 이름표를 손으로 적어 보내는 길 자체가 없어졌습니다.

6 기억은 내 것 · 그만두는 법

계속 쓸 때

원본은 계속 내 저장소에

기억이 쌓이는 곳은 여러분 계정의 비공개 저장소입니다. 언제든 GitHub에서 직접 열어 눈으로 읽을 수 있고, 나무 쪽이 들여다보지 않습니다.

그만둘 때

주소를 폐기하면 끝

내 페이지에서 주소를 폐기하면 됩니다. 원하시면 GitHub 설정에서 나무 앱의 권한까지 회수하세요. 저장소는 원래부터 여러분 계정에 있으니 그대로 남습니다.

💡파일도 마찬가지입니다 — 올린 파일의 몸통은 여러분 저장소의 attach_file/에 있고 나무는 "무슨 파일을 왜 올렸나"라는 이력만 갖습니다. 그림·PDF처럼 글자가 아닌 파일이나 큰 파일은 일회용 링크로 주고받는데, 이때는 파일이 AI를 아예 안 거쳐서 크기와 상관없이 빠릅니다.
