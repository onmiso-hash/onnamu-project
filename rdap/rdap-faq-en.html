Questions we are asked most often about RDAP lookups and about this service. For what each field in a response means, see Reading Results.

Q1. What exactly is RDAP?

It is the international standard for looking up registration data about domains, IP addresses and AS numbers. Its full name is the Registration Data Access Protocol. The IETF designed it to replace WHOIS, which had been in use for nearly forty years, and it now carries IETF standard status (STD 95).

The biggest difference is the shape of the answer. WHOIS returned free-form text that varied from server to server, while RDAP replies in structured JSON that software can read directly.

Q2. Is WHOIS dead?

Not yet, but the centre of gravity has clearly moved. ICANN requires gTLD operators such as .com and .org to run RDAP, and the obligation to keep legacy WHOIS on port 43 is being withdrawn in stages.

Some country-code TLDs still offer only WHOIS, or run both, which is why a handful of domains come back empty over RDAP.

Q3. Is this service free? Do I need an account?

It is free, and there is no account or API key to obtain.

It does run on a privately operated server, so we cannot promise commercial-grade availability. For business-critical lookups, keep each registry's official RDAP server in the loop as well.

Q4. Is there a rate limit?

The onnamu bootstrap service sets no quota of its own, but two things are worth knowing.

  • The final data comes from each registry's own server, so their limits (usually an HTTP 429) still apply.
  • The bootstrap files (/dns.json and friends) are refreshed from IANA once a day, so heavy users are better off downloading them and working locally.

Automated traffic heavy enough to threaten the server may be blocked.

Q5. Why are the registrant's name and contact details hidden?

Privacy law. Since the GDPR came into force, most registries withhold an individual registrant's name, address and phone number by default. Responses carry placeholders such as REDACTED FOR PRIVACY, or a web contact form URL instead of an email address.

Records held by companies are not personal data and are often shown in full. See the "redacted data" section of Reading Results for details.

Q6. Can I look up internationalised domain names?

Yes. Enter the name in its native script, or the xn-- punycode form; either works. The response carries punycode in ldhName and the human-readable form in unicodeName.

The TLD does of course need to operate an RDAP server for a result to come back.

Q7. I searched and got nothing back.

Usually it comes down to one of these.

  • The domain is not registered: an unregistered name returns 404.
  • Input format: drop any http:// prefix or trailing path and enter just the name, e.g. example.com.
  • The TLD has no RDAP server: still true of some country-code domains.
  • The authoritative server is down: that produces a 503; try again shortly.

Q8. How fresh is the data?

The registration data itself is live: it is produced by the authoritative registry at the moment you ask. We do not cache it and serve it back to you.

Only the bootstrap lists used to locate those servers are downloaded from IANA, once a day. Those lists change only when a new TLD appears or a server moves, so a daily refresh is ample.

Q9. Can I call this from my own application?

Yes. Request https://bootstrap.rdap.kr/domain/google.com and you get a 302 to the authoritative server; a client that follows redirects (curl -L) receives the final JSON in one go.

Cross-origin requests are allowed, so browser JavaScript can call the bootstrap service. Note that the destination server sets its own CORS policy, so some registries cannot be read directly from a browser. The About page documents the endpoints.

Q10. How do I tell whether a domain is still live?

Start with status. client hold or server hold means the name has been removed from DNS and does not resolve. inactive means no nameservers are set.

Be careful not to misread client transfer prohibited and similar values: those are ordinary anti-hijacking locks and appear on perfectly healthy domains.

Q11. Where do I report spam or abuse?

Find the entry in entities whose roles includes abuse; the email or phone number there is the official reporting channel. Failing that, the registrar contact is the next best option.

If the source is an IP address, look the address up and use the abuse contact of the network operator.

Q12. The domain expired — why can't I register it yet?

Because several grace periods follow expiry. Typically a redemption period of about 30 days, during which the former holder can still restore the name, then roughly five days of pending delete before it is released.

In practice, more than a month usually separates the expiration date from the day the name becomes available.

Q13. Do you log what I searched for?

Lookups are not stored in any way that links them back to you. We keep only what running the service requires: timestamp, IP address, country and requested path, all of it deleted automatically after 30 days.

Everything we record, and why, is set out in the Privacy Policy.

Q14. Can I use the results commercially?

The results are not onnamu's data; they belong to the registries that publish them. The terms therefore follow each registry's policy, which is often stated in the notices block of the response.

Bulk harvesting for marketing and any use for spam are generally prohibited. Terms for this service itself are in the Terms of Service.

Q15. I want my personal data removed.

Domain registration data is not ours to hold or amend. The registrar and registry where the domain was registered maintain it, so corrections and deletions have to be requested from them.

For the access records kept on our own server, write to the address in the Privacy Policy.
