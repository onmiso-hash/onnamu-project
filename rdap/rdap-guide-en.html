What happens when you press Search?

No single server holds registration data for the whole Internet. Each registry keeps its own domain records, and each Regional Internet Registry (RIR) keeps its own address records, so a lookup happens in two steps.

  1. Find who to ask (bootstrap). .com belongs to Verisign, 8.8.8.8 to ARIN. We look the authoritative server up in the registry files IANA publishes, which onnamu RDAP downloads once a day.
  2. Hand the query over (redirect). The service answers with an HTTP 302 pointing at that server, and the registration data itself comes from there, not from us.

What you see on screen is the registry's own response, passed through untouched. So when a field comes back empty, the reason is usually written into that registry's disclosure policy.

Fields common to every response

Whatever you look up, the response is built on the same skeleton, laid out in RFC 9083.

Field Meaning
rdapConformanceWhich specifications this response follows. Usually rdap_level_0, plus extension names such as redacted.
objectClassNameWhat this block is: domain, nameserver, entity, ip network or autnum.
handleThe registry's own identifier for the object, e.g. 2138514_DOMAIN_COM-VRSN.
linksrel: "self" is this object's own RDAP URL; rel: "related" points at further material such as the registrar's record.
noticesStatements about the service itself, such as terms of use and privacy notices. They say nothing about the object you looked up.
remarksNotes attached to the object itself, such as "some fields have been withheld for privacy".
port43Hostname of the legacy WHOIS server, when one is still operated.
langLanguage of the response text; almost always en.

Reading a domain response

Here is what a lookup for google.com returns, with the longer parts trimmed away.

{
  "objectClassName": "domain",
  "handle": "2138514_DOMAIN_COM-VRSN",
  "ldhName": "GOOGLE.COM",
  "status": ["client delete prohibited", "client transfer prohibited"],
  "events": [
    { "eventAction": "registration",  "eventDate": "1997-09-15T04:00:00Z" },
    { "eventAction": "expiration",    "eventDate": "2028-09-14T04:00:00Z" },
    { "eventAction": "last changed",  "eventDate": "2019-09-09T15:39:04Z" }
  ],
  "nameservers": [ { "objectClassName": "nameserver", "ldhName": "NS1.GOOGLE.COM" } ],
  "entities": [ { "objectClassName": "entity", "roles": ["registrar"] } ],
  "secureDNS": { "delegationSigned": false }
}
Field Description
ldhNameThe name in letters, digits and hyphens only. Internationalised names appear here as xn-- punycode.
unicodeNameThe human-readable form, e.g. 한국.kr. Often absent for ASCII-only names.
statusCurrent locks and holds; each value is explained in the table below.
eventsRegistration, expiry and change timestamps. All times are UTC (trailing Z).
entitiesPeople and organisations, separated by roles.
nameserversThe DNS servers that actually answer for this domain.
secureDNSDNSSEC settings. delegationSigned: true means the zone is signed.

🔒 A dictionary of status values

These values come from the domain provisioning protocol (EPP), reworded for RDAP. There is a trick to reading them: a client prefix means the registrar set the lock, while server means the registry did. Registry locks are the heavier ones, and they usually follow a dispute or legal action.

Value Meaning
activeIn normal use, with no restriction applied.
client transfer prohibitedTransfers to another registrar are blocked. Registrars commonly set this by default to prevent theft, so on its own it says nothing is wrong.
client delete prohibitedProtects the name from accidental deletion.
client update prohibitedChanges to nameservers or contacts are locked.
client hold · server holdThe domain has been pulled out of DNS and no longer resolves. Non-payment, abuse reports and disputes are the usual causes.
pending transferA registrar transfer is under way; it usually completes within five days.
pending deleteThe final stage of deletion. When it ends the name becomes available again.
redemption periodGrace period after expiry during which the original holder can still restore the name for a fee.
add period · renew periodThe window right after registration or renewal, during which cancellation may be refundable.
inactiveNo nameservers are set, so the domain does not work.
validated · pending validationWhether contact verification has been completed. Missing it can suspend the domain.
associatedMostly seen on contacts, meaning the record is linked to something in use.

How to read the dates

Every entry pairs what happened (eventAction) with when it happened (eventDate). Times are UTC, as in 2028-09-14T04:00:00Z.

eventAction Meaning
registrationWhen the object was first registered, which tells you the age of the domain.
expirationWhen the current term ends. Nothing is deleted on that day; several grace periods follow first.
last changedThe last time the registration record was modified.
transferWhen the sponsoring registrar last changed.
last update of RDAP databaseWhen the database behind this response was last refreshed. That is not the same as when the domain changed, which trips people up.
deletion · reinstantiationWhen the object was deleted, and when it was restored.

People and organisations live in entities

Contacts live in the entities array. Look at the roles on each one to see who you are dealing with.

  • registrant: the holder of the domain
  • administrative: the administrative contact
  • technical: handles nameservers and technical issues
  • billing: handles payment
  • registrar: the company through which the name was registered
  • reseller: a reseller working under that registrar
  • abuse: the channel for spam and abuse reports. If you are looking for somewhere to file a complaint, this is it.
  • sponsor · noc: sponsoring organisation and network operations centre, mostly on IP and ASN records

Why does vcardArray look like that?

Names, addresses and phone numbers are carried in vcardArray, a jCard structure. All those nested brackets look alarming at first, but the rule is simple: every line is [property, parameters, type, value].

["vcard", [
  ["version", {}, "text", "4.0"],
  ["fn",      {}, "text", "Google LLC"],
  ["adr",     { "cc": "US" }, "text", ["", "", "", "Mountain View", "CA", "94043", "US"]],
  ["email",   {}, "text", "abuse@example.com"],
  ["tel",     { "type": "voice" }, "uri", "tel:+1.6502530000"]
]]

fn is the display name, org the organisation, adr the postal address (PO box, extended address, street, city, region, postcode, country) and kind tells you whether it is an individual or an organisation. The onnamu web client renders this array as a readable table.

Nameservers and DNSSEC

A nameserver entry carries its ldhName, and sometimes ipAddresses split into v4 and v6. Those addresses are glue records. When a nameserver sits inside the very domain it serves, there is nowhere to ask for its address, and glue records break that loop.

secureDNS describes the DNSSEC configuration.

  • delegationSigned: whether the delegation is signed. false means DNSSEC is not in use.
  • dsData: the signature fingerprint: keyTag, algorithm, digestType and digest.
  • maxSigLife: maximum signature lifetime in seconds; usually absent.

IP network and AS number responses

Looking up an IP address returns the whole block it belongs to, not just that single address.

Field Description
startAddress · endAddressFirst and last address of the allocated block.
ipVersionEither v4 or v6.
nameThe label given to the block (e.g. GOGL), a clue to who operates it.
typeHow it was allocated (DIRECT ALLOCATION, ASSIGNED PA, …), distinguishing direct holdings from sub-allocations.
countryThe registered country code. This is a paperwork value, so the machines may well sit somewhere else.
parentHandleIdentifier of the block this one was carved out of.
cidr0_cidrsAn extension expressing the same range in CIDR form, e.g. 8.8.8.0/24.
startAutnum · endAutnumFor AS lookups: the range of AS numbers assigned.

An AS number identifies an organisation that announces routes on the Internet. 15169 is Google, 3356 is Lumen.

Why is the registrant's name missing?

Classic WHOIS published personal names, addresses and phone numbers in full. Since the GDPR took effect in 2018, holding back an individual registrant's details has become the norm, so responses often show:

  • placeholders such as REDACTED FOR PRIVACY or DATA REDACTED
  • a web contact form URL in place of an email address
  • an explicit list of what was withheld and why, on servers that implement the redacted extension (RFC 9537)

Domains held by companies are not personal data, so those records often appear in full. Requesters with a legitimate basis, such as law enforcement or rights holders, can obtain the details through the registry's own process. That is exactly why RDAP was built to vary its answer by requester, something WHOIS could never do.

When nothing comes back

When something goes wrong, RDAP says so in structured JSON as well.

{
  "errorCode": 404,
  "title": "Not Found",
  "description": ["The requested object does not exist."]
}
  • 404: not registered, or not held by that server. Nine times out of ten the name simply has not been registered.
  • 400 and 422: the query does not match the expected format. Check for stray spaces or a leading http://.
  • 429: too many queries in a short time. Wait a moment and retry.
  • 501: that registry does not support this kind of lookup.
  • 503: the authoritative server is down or under maintenance. That is almost always their side rather than ours.
  • No response at all: the TLD does not run an RDAP server yet. A few country-code domains are still in that position.

Things people commonly get wrong

  1. Expiry is not availability. After expiration come the redemption period and pending delete, usually well over a month before anyone can register the name.
  2. client … prohibited is not a warning. Most registrars set these locks by default to prevent hijacking.
  3. country is not server location. It is the country on the registration paperwork, and the hardware may sit elsewhere.
