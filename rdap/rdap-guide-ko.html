조회 버튼을 누르면 무슨 일이 일어나나요?

RDAP에는 "전 세계 정보를 다 갖고 있는 하나의 서버"가 없습니다. 도메인은 각 레지스트리가, IP 주소는 각 대륙 인터넷 주소 관리기관(RIR)이 자기 몫의 데이터를 각자의 서버에 두고 있습니다. 그래서 조회는 두 단계를 거칩니다.

  1. 어디에 물어볼지 찾기(부트스트랩) — .com은 베리사인, 8.8.8.8은 ARIN처럼, 입력한 값을 담당하는 서버가 어디인지 IANA가 발행하는 목록에서 찾습니다. 온나무 RDAP은 이 목록을 하루 한 번 IANA에서 내려받아 보관합니다.
  2. 담당 서버로 넘기기(리다이렉트) — 찾아낸 주소로 HTTP 302 응답을 돌려줍니다. 실제 등록 정보는 그 담당 서버가 직접 만들어 보내 줍니다.

즉 화면에 보이는 등록 정보는 온나무가 만든 것이 아니라 권위 있는 레지스트리가 그 순간 내려 준 원본입니다. 그래서 "왜 이 항목이 비어 있나요" 같은 물음의 답은 대부분 해당 레지스트리의 공개 정책에 있습니다.

모든 응답에 공통으로 들어가는 것

RDAP 응답은 어떤 종류를 조회하든 아래 뼈대를 공유합니다(RFC 9083).

필드 무엇을 뜻하나
rdapConformance이 응답이 따르는 규격 목록. 보통 rdap_level_0이 들어 있고, 확장을 쓰면 redacted처럼 확장 이름이 덧붙습니다.
objectClassName이 덩어리가 무엇인지. domain · nameserver · entity · ip network · autnum 중 하나입니다.
handle레지스트리가 이 객체에 붙인 고유 번호. 도메인은 2138514_DOMAIN_COM-VRSN 같은 모양입니다.
links관련 주소들. rel: "self"는 이 객체 자신의 RDAP 주소, rel: "related"는 등록대행자 쪽 정보처럼 이어지는 자료입니다.
notices서비스 전체에 붙는 안내(이용 조건, 개인정보 고지 등). 조회한 대상이 아니라 서버에 대한 설명입니다.
remarks조회한 그 대상에 붙는 비고. "일부 항목은 개인정보 보호로 가려졌다" 같은 문구가 여기 옵니다.
port43같은 정보를 옛 방식(WHOIS)으로 받을 수 있는 서버 이름. 남아 있으면 적혀 있고, 없으면 생략됩니다.
lang응답에 쓰인 언어 표시. 대부분 en입니다.

도메인 응답 읽기

google.com을 조회했을 때 돌아오는 응답을 줄여 보면 이런 모양입니다.

{
  "objectClassName": "domain",
  "handle": "2138514_DOMAIN_COM-VRSN",
  "ldhName": "GOOGLE.COM",
  "status": ["client delete prohibited", "client transfer prohibited"],
  "events": [
    { "eventAction": "registration",  "eventDate": "1997-09-15T04:00:00Z" },
    { "eventAction": "expiration",    "eventDate": "2028-09-14T04:00:00Z" },
    { "eventAction": "last changed",  "eventDate": "2019-09-09T15:39:04Z" }
  ],
  "nameservers": [ { "objectClassName": "nameserver", "ldhName": "NS1.GOOGLE.COM" } ],
  "entities": [ { "objectClassName": "entity", "roles": ["registrar"] } ],
  "secureDNS": { "delegationSigned": false }
}
필드 설명
ldhName영문자·숫자·붙임표로만 적은 도메인 이름. 한글 도메인은 여기에 xn--로 시작하는 퓨니코드가 들어갑니다.
unicodeName사람이 읽는 원래 이름. 한국.kr처럼 표시되며, 영문 도메인에는 아예 없을 수 있습니다.
status현재 잠금·보류 상태 목록. 아래 표에서 값 하나하나를 설명합니다.
events등록·만료·변경 시각. 시각은 모두 UTC(끝의 Z)이며 한국 시간은 9시간을 더합니다.
entities사람·회사 정보. 등록자·관리자·기술 담당·등록대행자가 roles로 구분됩니다.
nameservers이 도메인의 주소를 실제로 답해 주는 DNS 서버들.
secureDNSDNSSEC 서명 여부. delegationSigned: true면 위조 방지 서명이 걸려 있습니다.

🔒 status 값 사전

status에 담기는 값은 도메인 등록 시스템(EPP)에서 온 용어를 RDAP 표기로 옮긴 것입니다. 앞에 client가 붙으면 등록대행자가 건 잠금, server가 붙으면 레지스트리가 건 잠금입니다. 레지스트리 잠금이 더 강하며 대개 분쟁·법적 사유로 걸립니다.

값 뜻
active정상 사용 중. 아무 제한이 걸려 있지 않습니다.
client transfer prohibited다른 등록대행자로 옮기는 것이 막혀 있음. 도난 방지용 기본 설정인 경우가 많아, 문제가 있다는 뜻이 아닙니다.
client delete prohibited실수로 지우는 것을 막아 둔 상태.
client update prohibited네임서버·연락처 등 정보 변경이 잠겨 있는 상태.
client hold · server hold도메인이 DNS에서 빠져 실제로 접속되지 않는 상태. 미납·신고·분쟁이 흔한 사유입니다.
pending transfer등록대행자 이전이 진행 중. 보통 5일 안에 끝납니다.
pending delete삭제 절차 마지막 단계. 이 상태가 끝나면 누구나 등록할 수 있게 풀립니다.
redemption period만료 뒤 유예 기간. 원래 주인이 추가 비용을 내고 되살릴 수 있는 마지막 기회입니다.
add period · renew period갓 등록했거나 갓 연장한 직후의 기간. 이 동안 취소하면 환불되는 규정이 있습니다.
inactive네임서버가 지정되지 않아 도메인이 동작하지 않는 상태.
validated · pending validation연락처 확인 절차를 마쳤는지 여부. 확인을 놓치면 도메인이 정지될 수 있습니다.
associated주로 연락처(entity)에 붙으며, 어딘가에 연결되어 쓰이고 있음을 뜻합니다.

events — 날짜 읽기

각 항목은 eventAction(무슨 일)과 eventDate(언제) 한 쌍입니다. 시각은 2028-09-14T04:00:00Z처럼 UTC로 적히므로, 한국 시간으로 보려면 9시간을 더합니다.

eventAction 뜻
registration최초 등록 시각. 도메인의 나이를 알 수 있는 값입니다.
expiration현재 등록 기간이 끝나는 시각. 이날 바로 삭제되는 것은 아니며 유예 기간이 이어집니다.
last changed등록 정보가 마지막으로 바뀐 시각(네임서버 변경, 연장 등).
transfer등록대행자가 바뀐 시각.
last update of RDAP database이 응답을 만든 데이터베이스가 갱신된 시각. 도메인이 바뀐 시각이 아니라 자료 갱신 시각입니다.
deletion · reinstantiation삭제된 시각, 되살아난 시각.

entities — 사람과 회사 정보

연락처는 entities 배열에 담기고, 각 항목의 roles가 그 역할을 말해 줍니다.

  • registrant — 도메인의 실제 주인
  • administrative — 운영·계약을 맡은 관리 담당
  • technical — 네임서버 등 기술 문제를 처리하는 담당
  • billing — 결제 담당
  • registrar — 등록을 대행한 업체(가비아, GoDaddy 등)
  • reseller — 등록대행자의 재판매 업체
  • abuse — 스팸·침해 신고를 받는 창구. 신고할 곳을 찾는다면 이 항목을 보면 됩니다.
  • sponsor · noc — 후원 주체, 망 운영 센터(주로 IP·ASN 조회에서 보입니다)

vcardArray가 왜 이렇게 생겼나요?

이름·주소·전화번호는 vcardArray라는, 전자 명함(jCard) 형식으로 들어 있습니다. 처음 보면 낯설지만 규칙은 단순합니다 — [항목 이름, 부가정보, 자료형, 값] 네 칸짜리 줄이 이어질 뿐입니다.

["vcard", [
  ["version", {}, "text", "4.0"],
  ["fn",      {}, "text", "Google LLC"],
  ["adr",     { "cc": "US" }, "text", ["", "", "", "Mountain View", "CA", "94043", "US"]],
  ["email",   {}, "text", "abuse@example.com"],
  ["tel",     { "type": "voice" }, "uri", "tel:+1.6502530000"]
]]

fn은 표시 이름, org는 소속, adr는 주소(사서함·상세주소·동네·시·도·우편번호·국가 순), kind는 개인인지 단체인지를 뜻합니다. 온나무 웹 클라이언트는 이 배열을 사람이 읽기 좋은 표로 바꿔서 보여 줍니다.

네임서버와 DNSSEC

네임서버 항목에는 이름(ldhName)과 함께 ipAddresses가 붙기도 합니다. v4·v6로 나뉜 이 주소는 이른바 글루 레코드로, 네임서버가 자기 도메인 안에 있을 때(ns1.google.com이 google.com을 담당하는 경우) 닭과 달걀 문제를 푸는 역할을 합니다.

secureDNS는 DNSSEC 설정을 담습니다.

  • delegationSigned — 위조 방지 서명이 걸려 있는지 여부. false면 DNSSEC를 쓰지 않는 도메인입니다.
  • dsData — 서명 지문. keyTag(열쇠 번호), algorithm(서명 방식 번호), digestType(요약 방식), digest(지문 값)로 이뤄집니다.
  • maxSigLife — 서명의 최대 유효 기간(초). 없는 경우가 더 많습니다.

IP 주소와 AS 번호 응답

IP를 조회하면 그 주소 하나가 아니라 그 주소가 속한 대역 전체의 정보가 돌아옵니다.

필드 설명
startAddress · endAddress할당된 대역의 처음과 끝 주소.
ipVersionv4 또는 v6.
name대역에 붙은 이름표(예: GOGL). 운영 주체를 짐작하는 실마리입니다.
type배정 방식(DIRECT ALLOCATION, ASSIGNED PA 등). 기관이 직접 받은 대역인지, 상위에서 나눠 받은 대역인지를 구분합니다.
country등록된 국가 코드. 실제 서버가 있는 나라와 다를 수 있습니다 — 등록 서류상의 국가일 뿐입니다.
parentHandle이 대역을 나눠 준 상위 대역의 번호.
cidr0_cidrs같은 대역을 8.8.8.0/24 같은 CIDR 표기로 적은 확장 항목.
startAutnum · endAutnumAS 번호 조회에서 나오는 값으로, 배정된 번호 구간을 뜻합니다.

AS 번호(autnum)는 인터넷에서 경로를 광고하는 조직 단위 번호입니다. 예를 들어 15169는 구글, 3356은 루멘의 번호입니다.

왜 등록자 이름이 안 보이나요 — 가려진 정보

예전 WHOIS는 개인의 이름·주소·전화번호를 그대로 공개했습니다. 유럽 개인정보보호법(GDPR)이 2018년 시행된 뒤로는 개인 등록자의 정보를 기본적으로 가리는 것이 표준 관행이 되었습니다. 그래서 응답에서 이런 모습을 자주 보게 됩니다.

  • 값 자리에 REDACTED FOR PRIVACY, DATA REDACTED 같은 문구가 들어 있음
  • 이메일 대신 https://...로 시작하는 문의 양식 주소가 들어 있음
  • redacted 확장(RFC 9537)을 쓰는 서버는 어떤 항목을 왜 가렸는지를 따로 적어 줍니다

회사·기관 명의로 등록된 도메인은 개인정보가 아니므로 그대로 보이는 경우가 많습니다. 또 법 집행기관·지식재산권자처럼 정당한 사유가 있는 요청자에게는 레지스트리가 별도 절차로 정보를 제공합니다. 이것이 RDAP이 WHOIS와 달리 요청자에 따라 응답을 달리 줄 수 있도록 설계된 이유입니다.

결과가 안 나올 때 — 오류 응답 읽기

RDAP은 오류도 정해진 JSON으로 돌려줍니다.

{
  "errorCode": 404,
  "title": "Not Found",
  "description": ["The requested object does not exist."]
}
  • 404 — 등록되지 않았거나, 해당 서버가 그 자료를 갖고 있지 않음. 미등록 도메인일 가능성이 가장 큽니다.
  • 400 · 422 — 입력 형식이 규격에 맞지 않음. 도메인에 공백이나 http://가 섞이지 않았는지 확인해 보세요.
  • 429 — 짧은 시간에 너무 많이 물었음. 잠시 뒤 다시 시도하면 됩니다.
  • 501 — 해당 레지스트리가 그 조회 종류를 지원하지 않음.
  • 503 — 담당 레지스트리 서버가 점검 중이거나 응답하지 않음. 온나무 서버가 아니라 상대 서버 사정인 경우가 많습니다.
  • 응답이 아예 없음 — 그 TLD가 아직 RDAP 서버를 운영하지 않는 경우입니다. 일부 국가 도메인이 여기에 해당합니다.

자주 헷갈리는 세 가지

  1. 만료일 ≠ 사용 가능일 — expiration이 지나도 유예 기간(redemption period, pending delete)이 보통 한 달 넘게 이어집니다. 그 도메인을 노린다면 이 기간이 모두 끝나야 합니다.
  2. client ~ prohibited는 경고가 아닙니다 — 대부분의 등록대행자가 도난 방지를 위해 기본으로 걸어 두는 잠금입니다.
  3. country는 서버 위치가 아닙니다 — IP 대역에 적힌 국가는 등록 서류상의 국가이며, 실제 장비는 다른 나라에 있을 수 있습니다.
