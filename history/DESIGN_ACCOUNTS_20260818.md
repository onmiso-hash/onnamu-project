## 갤러리 폴더 권한 — 실측한 함정 2개

"지인은 처음에 `public`만"을 실행하는 순간 바로 부딪히는 자리다. 둘 다 지금 코드에 있다.

### 함정 1 — public만 가진 계정이 올리면 결국 public에 올라간다

`gallery/app.py:292-294`(`/upload`)와 `384-385`(`/upload_complete`) **두 곳에 같은 코드**가 있다.

```python
writable = [f for f in folders if f != "public"]
target_folder = writable[0] if writable else folders[0]
```

일반 계정의 `public` 쓰기를 막으려는 의도로 보이지만, **쓸 폴더가 없으면 `folders[0]`(=public)으로 되돌아간다.**
지금은 계정이 둘뿐이고 둘 다 `public` 아닌 폴더를 갖고 있어서 드러나지 않았다.

### 함정 2 — 폴더를 하나도 안 준 계정이 올리면 500

같은 줄의 `folders[0]`이 빈 목록을 집는다. 관리 화면에서 폴더를 전부 끌 수 있게 되는 순간 실제로 일어난다.

### 제안 — `can_upload` 한 칸으로 둘 다 없앤다

계정에 `can_upload`(기본 꺼짐)를 두고, **켜져 있고 `public`이 아닌 폴더가 하나라도 있을 때만** 업로드 화면과 통로를 연다.
그러면 위 두 자리에 도달할 수 없게 되어 함정이 함께 사라진다.
관리자는 종전대로 폴더를 골라 올린다.

## Chronicle AI 빗장 풀기

`isAdmin` 하나가 **두 뜻**으로 쓰이고 있다 — (가) 문지기 (나) 19금 열람.
빗장을 풀면 (가)는 사라지고 (나)만 `canAdult`로 갈라야 한다. 관리자는 자동으로 참.

| 파일 | `isAdmin` 출현 줄 | 비고 |
|---|---|---|
| `studio/server.js` | 23 | |
| `studio/store.js` | 6 | |
| `studio/app.js` | 20 | 이 중 8줄만 같은 줄에 `adult-19`/`19금`이 함께 있다 |
| **합** | **49** | |

⚠ **49줄을 일괄 치환하지 말 것.** 전부가 19금 뜻은 아니다 — 한 줄씩 판정한다.
이 작업에서 "한 곳에서 옳던 규칙이 다른 자리에서 뜻이 달라진" 결함이 이미 세 번 났다.

### 처음으로 실행되는 코드

19금 가리기 갈래는 `adminOnly` 빗장 때문에 **한 번도 실행된 적이 없다**.
빗장 해제 시 처음 돈다. 배포 전 `adult_ok=false` 계정으로 실측 필수:

1. 19금 인물이 목록에 안 뜨는가
2. 19금 대화 id를 직접 두드리면 404인가 (감춤과 없음이 구분되면 안 됨)
3. 그 계정이 인물을 저장할 때 관리자의 19금 인물이 지워지지 않는가

`/admin/accounts` — 관리자만.
목록(아이디·관리자·19금·볼 폴더·올리기·잠김·마지막 로그인) · 만들기 · 권한 변경 · 잠그기/풀기 · 비밀번호 초기화 · **지우기**.

⚠ **막아야 할 구멍**: `portal/auth_helper.py:73-82`의 `login_required`는
`X-API-Key == SECRET_KEY`면 무조건 관리자로 통과시킨다(배포 자동화용).
계정 관리 통로에 이게 걸리면 열쇠 하나로 계정 생성·권한 상승이 가능하다.
**계정 관리 통로만은 이 우회를 차단하고 쿠키 로그인만 받는다.**
