# 2026-08-19 — 신분·권한 판정을 한 벌로 모으다

## 왜 했나

2026-08-18 갤러리 신분 유출 사고의 진짜 원인은 "같은 규칙이 여러 벌로 복사돼 있어
한쪽만 고쳐진다"였다(그 작업에서만 같은 모양이 네 번 나왔다). 갤러리 한 곳만 고치고
끝내면 다음 사고는 다른 서비스에서 난다. 그래서 규칙 자체를 한 벌로 모았다.

## 먼저 잰 것 — 지금 어떤 상태였나

| 서비스 | 신분(누구인가) | 권한(무엇을 할 수 있나) |
|---|---|---|
| 포털 | 공용 출입증 — 맞음(발급자 본인) | **묻지 않음** |
| 갤러리 | 08-18에 고침 — 맞음 | 60초마다 포털에 물음 |
| 스튜디오 | 공용 출입증 — 맞음(자기 사본 없음) | 60초마다 포털에 물음 |
| 게임·도메인조회 | 로그인 없음 | 해당 없음 |

**신분을 잘못 재는 곳은 남아 있지 않았다.** 대신 두 가지가 나왔다.

### ① 포털 관리자 통로 4곳이 30일 묵은 값을 믿고 있었다

`/stats`, `/api/news/save`, `/api/work/save`, `/api/debug/deploy-log`.
`login_required(admin_only=True)`가 출입증에 박힌 `is_admin`만 봤다. 출입증이 30일짜리라
관리자에서 내린 사람이 최대 30일간 계속 통과한다. 계정 관리 화면만 예외로 막혀 있었다.

### ② 기계 출입증이 스튜디오에서 401로 막히고 있었다 (실측)

포털이 계정을 지울 때 스튜디오에 자료 정리를 시키며 `system_portal` 이름의 출입증을 만든다.
그런데 스튜디오는 그 이름으로 포털에 권한을 물었고, 계정표에 없으니 `{"exists": false}` →
401. 즉 **계정을 지워도 Chronicle AI 쪽 자료가 남았다.**

실측 근거(미니PC에서 직접):
- `GET /api/auth/permissions/system_portal` → `{"exists":false}`
- 같은 출입증으로 스튜디오 `/api/user-info` → `401`

## 무엇을 했나

### 규칙 한 벌 — `shared/auth_common.py`

출입증 만들기·검사, 신분 판정(`current_identity`), 권한 적용(`apply_permissions`),
기계 신분 판정(`is_machine_identity`), 로그인 화면으로 보내기를 여기 하나에 모았다.

도커가 서비스 폴더 하나만 담아 이미지를 만들기 때문에 `portal/`·`gallery/`에 **사본**이
필요하다. 사본은 `scripts/sync_auth_common.sh`로 내려보내고, 원본과 한 글자라도 다르면
push가 막힌다. 사본을 직접 고치지 말 것.

여기 **없는 것**: 권한을 어디서 가져오는가. 포털은 자기 표를 직접 보고, 나머지는 포털에
물어본다. 가져온 뒤의 판정은 이 파일 하나가 정한다.

### 포털

- `login_required`가 매 요청 지금 표를 본다(`set_permission_source`로 `app.py`가 꽂아 준다).
  자기 자신에게 HTTP로 묻지 않는다 — 서로 부르는 고리를 피한다.
- 첫 화면·로그인 화면이 쿠키를 직접 읽던 것을 공통 판정으로 넘겼다.
  첫 화면의 관리자 메뉴도 이제 지금 표를 보고 정한다.
- `/api/auth/permissions`가 포털 자신이 쓰는 답과 같은 함수(`account_permissions`)에서 나온다.
- `system_`으로 시작하는 아이디는 계정으로 만들 수 없다 — 그 이름은 권한 조회를 건너뛰므로
  사람이 가지면 권한을 내려도 반영되지 않는다.

### 갤러리

판정 규칙을 전부 공통 파일에 넘기고, 갤러리에만 있는 것(손잡기로 받은 출입증 심기,
사본 갈아 끼우기, 올리기 허용 조건)만 남겼다. 겉으로 보이는 동작은 그대로다 —
기존 검사 10개가 모두 그대로 통과한다.

### 스튜디오

같은 언어가 아니라 사본 대조가 안 된다. 기계 신분 규칙만 같은 모양으로 맞추고
(`isMachineIdentity`), 동작이 같은지를 검사로 잰다.

## 막는 검사 — `scripts/check_identity_common.py` (15개, push 전 자동)

1. 사본 2개가 원본과 글자까지 같은가
2. 출입증 검사·발급을 서비스가 따로 만든 자리가 없는가
3. 공용 출입증을 신분 판정 밖에서 직접 읽는 자리가 없는가
4. 포털이 '지금 권한 묻기'를 **실제로 꽂아 두었는가** (app.py를 import해서 잰다)
5. 관리자에서 내린 사람이 옛 출입증으로 막히는가 / 살아 있는 관리자는 통과하는가 /
   잠긴 계정·지워진 계정은 막히는가 / 갤러리 사본만으로는 못 들어가는가 /
   기계 출입증은 통과하는가 / 배포 열쇠 우회가 그대로 사는가
6. 스튜디오가 기계 출입증을 받아들이는가, 못 물었을 때 버티는가 (node로 실제 실행)

검사가 정말 막는지 일부러 깨뜨려 확인했다 — 사본을 고쳤을 때, 권한 묻기 배선을 뺐을 때
각각 push가 막혔다.

## 남은 것

스튜디오는 언어가 달라 규칙이 두 벌이다. 사본 대조 대신 동작 대조로 묶어 두었지만
완전히 한 벌은 아니다.
