## 0단계 — 스튜디오가 모든 계정의 자료 파일을 로그인 없이 내주고 있었다

### 무엇이 문제였나

- `server.js`의 `app.use(express.static(__dirname))`가 스튜디오 폴더를 **통째로** 열었다.
  컨테이너 안에서 `__dirname`=`/app`, 볼륨이 `/app/data`에 붙으므로
  `/data/users/<아이디>/characters/*.json`, `.../conversations/<id>/turns.jsonl`이 그대로 나갔다.
- 빗장(`authHelper.js`)은 **확장자가 있는 요청을 검사 없이 통과**시킨다(css·js용 우회).
  그래서 로그인조차 필요 없었다. `canAdult` 판정·404 감춤을 통째로 건너뛴다(19금 대화 포함).
- 같은 이유로 `server.js`·`store.js` 소스와 `/data/uploads`의 그림도 비로그인에게 나갔다.

실측(로컬, 수정 전 코드 그대로 띄움): 비로그인 `GET /data/users/bob/characters/c1.json` → **200**,
`/server.js` → 200, `/data/uploads/*.png` → 200.

### '/data'로 시작하면 막는 방식은 뚫린다

`/%64ata/users/...`, `/data%2fusers%2f...`처럼 인코딩한 주소는 express의 경로 짝짓기를 비껴가지만
express.static은 풀어서 파일을 찾는다 → **200**(실측). 그래서 막을 것을 고르지 않고 **내줄 것을 고른다.**

### 무엇을 했나

- `server.js`: 폴더 통째 공개를 없애고 `PUBLIC_FILES`(index.html·app.js·style.css)만 `sendFile`.
  화면 파일을 새로 만들면 이 목록에 적어야 한다.
- `/data/uploads`: `authMiddleware({ protectFiles: true })`를 앞에 건다. 로그인 없으면 **401**
  (`<img>`가 받는 자리라 로그인 창으로 넘기지 않는다). 짝짓기와 내주기가 같은 마운트라 인코딩 우회가 없다.
- `authHelper.js`: `protectFiles` 선택지 추가 — 확장자 우회를 끄고 API처럼 401로 답한다.
- 바깥 공유 링크 유지는 요구사항이 아니다(사용자 확정). 다른 서비스가 `/data/uploads`를 가져다 쓰는 곳 없음(저장소 검색).

## 1차 — 감정 레지스트리(12종 + 19금 lust)

### 무엇을 했나

- `studio/emotionRegistry.js` 신설 — 일반 스크립트 + UMD 꼬리(브라우저 `window.EmotionRegistry`, 노드 `require`).
  `app.js`가 모듈이 아니라 `export`를 쓸 수 없다(설계 v1의 ESM안 보정).
  - 신규 7: surprised(놀람)·love(설렘)·teasing(장난)·tired(지침)·thinking(생각)·fear(두려움)·crying(울음). 19금 전용 lust(욕정).
  - 대체 사슬은 표의 `fallback` 한 칸에만: crying·fear→sad, love·teasing→happy, lust→blush, 나머지→normal.
- `app.js`: 5개짜리 배열·삼항 라벨을 모두 레지스트리 조회로 교체(초기화·프리셋 불러오기 2곳·미리보기·생성·업로드 실패 복구·말풍선·프로필·응답 기본값).
  - 미리보기 3곳이 같은 루프를 복사해 두던 것을 `refreshCharacterImagePreviews()` 하나로 모음. 칸도 이 함수가 그린다(DOM id `img-preview-<id>` 유지).
  - 19금 전용 칸은 `canAdult`이고 설정창 수위(=인물 기본 수위)가 19금일 때만. AI 스키마 enum은 `canAdult`이고 **대화** 수위가 19금일 때만.
  - AI가 모르는 감정 id를 내면 normal로 저장.
  - `generateCharacterImages`: `characterImages = {}`로 비우던 결함 제거. 기본은 **빈 칸만** 생성, '전부 다시 생성' 체크 시에만 전부.
    중간에 실패해도 이미 만든 그림은 남고, 안내창이 칸을 눌러 직접 올리라고 알려준다.
  - **생성본도 `/api/upload-image`로 파일화** — 예전에는 base64를 그대로 인물 JSON에 담았다(설계 v1이 "파일화한다"고 적었으나 실제로는 아니었다).
    옛 인물에 이미 들어 있는 base64는 이사하지 않는다(그대로 표시되고, 다시 만들면 주소로 바뀐다).
- `server.js`: `/api/upload-image`가 감정 id를 레지스트리로 확인(파일 이름에 들어가므로 `../` 차단),
  파일 앞머리로 png·jpg·webp만 받고 확장자를 실제 형식으로 붙인다(예전엔 무엇이든 `.png`). `PUBLIC_FILES`에 레지스트리 추가.
- `index.html`: 하드코딩 5칸 제거, '전부 다시 생성' 체크칸, `?v=20260923_0700`(style.css·emotionRegistry.js·app.js).
- `style.css`: 칸 6열(폰 480px 이하 4열).

생성 모델(Imagen 3)은 종료된 것으로 보이나(검색 결과, 공식 문서 직접 확인 못 함) 교체는 이 묶음 밖이다.
