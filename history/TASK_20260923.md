## 0단계 — 스튜디오가 모든 계정의 자료 파일을 로그인 없이 내주고 있었다

### 무엇이 문제였나

- `server.js`의 `app.use(express.static(__dirname))`가 스튜디오 폴더를 **통째로** 열었다.
  컨테이너 안에서 `__dirname`=`/app`, 볼륨이 `/app/data`에 붙으므로
  `/data/users/<아이디>/characters/*.json`, `.../conversations/<id>/turns.jsonl`이 그대로 나갔다.
- 빗장(`authHelper.js`)은 **확장자가 있는 요청을 검사 없이 통과**시킨다(css·js용 우회).
  그래서 로그인조차 필요 없었다. `canAdult` 판정·404 감춤을 통째로 건너뛴다(19금 대화 포함).
- 같은 이유로 `server.js`·`store.js` 소스와 `/data/uploads`의 그림도 비로그인에게 나갔다.

실측(로컬, 수정 전 코드 그대로 띄움): 비로그인 `GET /data/users/bob/characters/c1.json` → **200**,
`/server.js` → 200, `/data/uploads/*.png` → 200.

### '/data'로 시작하면 막는 방식은 뚫린다

`/%64ata/users/...`, `/data%2fusers%2f...`처럼 인코딩한 주소는 express의 경로 짝짓기를 비껴가지만
express.static은 풀어서 파일을 찾는다 → **200**(실측). 그래서 막을 것을 고르지 않고 **내줄 것을 고른다.**

### 무엇을 했나

- `server.js`: 폴더 통째 공개를 없애고 `PUBLIC_FILES`(index.html·app.js·style.css)만 `sendFile`.
  화면 파일을 새로 만들면 이 목록에 적어야 한다.
- `/data/uploads`: `authMiddleware({ protectFiles: true })`를 앞에 건다. 로그인 없으면 **401**
  (`<img>`가 받는 자리라 로그인 창으로 넘기지 않는다). 짝짓기와 내주기가 같은 마운트라 인코딩 우회가 없다.
- `authHelper.js`: `protectFiles` 선택지 추가 — 확장자 우회를 끄고 API처럼 401로 답한다.
- 바깥 공유 링크 유지는 요구사항이 아니다(사용자 확정). 다른 서비스가 `/data/uploads`를 가져다 쓰는 곳 없음(저장소 검색).

## 2차 — 대화별 장면(배경) + 무대

1. **PATCH 허용 칸 한 표로**: `server.js`의 PATCH 통로가 자기 배열을 들고 있어 `store.js`의 `META_PATCH_KEYS`와 두 벌이었다.
   `store.META_PATCH_KEYS`를 내보내 서버가 읽게 하고, 그 표에만 `sceneId`를 더했다.
2. **장면 레지스트리** `studio/sceneRegistry.js`(UMD, 감정 레지스트리와 같은 방식): studio·카페·사무실·교실·침실·밤거리·공원 석양·빗소리 창가.

   옛 `meta.json`은 고치지 않는다.
4. **화면**: `renderChatProfile`의 머리 부분을 무대(`.profile-stage` = 배경판 + 감정 초상 + 장면 이름표)로.
