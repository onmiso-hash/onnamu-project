# 📥 미디어 갤러리 대용량 파일 분할 업로드 및 영화관 연동 패치 (2026-06-14)

## 1. 개요 및 배경
* **문제 상황**: 900MB 이상의 대용량 동영상 파일을 업로드할 때, 기존 Cloudflare Tunnel의 100MB 요청 크기 제한 및 Flask 내장 개발 서버(Werkzeug)의 네트워크 수신 버퍼 타임아웃/블로킹 한계로 인해 네트워크 오류와 실패가 발생했습니다.
* **추가적 버그**: 대용량 업로드 성공 후에도 비디오 파일이 영화관(Movie Theater) 탭 목록에 표시되지 않았으며, 업로드 시작 시 이전 플래시 경고 배너가 초기화되지 않고 상단에 남아 있던 버그가 식별되었습니다.

## 2. 상세 해결 및 패치 내역

### A. 청크 분할 업로드(Chunked Upload) 기법 도입
* **백엔드 (`gallery/app.py`)**:
  * AJAX 호출용 `/upload_chunk` 및 `/upload_complete` 라우트를 신설하여 10MB 단위 조각 전송을 가능하게 했습니다.
  * API 호출 시 302 리다이렉트 꼬임 방지를 위해 API 전용 `401 Unauthorized` 인증 처리를 적용했습니다.
  * 조각 병합 시 `shutil.copyfileobj`를 이용한 디스크 간 스트리밍 병합으로 메모리 OOM을 차단하고, 실패 시 임시 병합 파일을 삭제하는 예외 복구 장치를 마련했습니다.
* **프론트엔드 (`gallery/templates/upload.html`)**:
  * 자바스크립트 `XMLHttpRequest` 및 `file.slice` API를 활용하여 10MB 단위 직렬 전송 루프를 구현했습니다.
  * 업로드 진행률 바에 `(1/90 조각 전송 중...)`과 같이 전송 상황을 시각화하고, 전송 개시 즉시 기존 화면의 이전 `.flash` 배너를 즉시 감추도록 처리했습니다.

### B. 미디어 분류 업로드 옵션 신설 및 도커 볼륨 권한 격리
* **디렉토리 분리**: 영화관 탭은 `/media/프로젝트폴더/movies/`를 스캔하지만 기존 업로드는 `/videos/`에 고정되어 있었던 비매칭 오류를 해결했습니다.
* **옵션 제공**: 업로드 UI에 미디어 분류(`일반 미디어 / 영화관 동영상`)를 신설하여 비디오 파일의 최종 저장 경로 분기를 백엔드에 연동했습니다.
* **도커 볼륨 권한 갱신 (`gallery/docker-compose.yml`)**:
  * `/media/public/movies`, `/media/private/movies`, `/media/family/movies` 디렉토리를 `:rw`(읽기/쓰기 가능)로 추가 마운트하여 최종 병합 시 `Read-only file system` 오류가 나지 않도록 차단했습니다.

### C. 영화관 메인 탭 캐시 오폭 버그 수정
* **오폭 캐시 제거**: 30일 미디어 불변 캐시 정책이 URL 전체 경로에 `'movies'` 키워드가 포함될 때도 적용되어, 영화관 화면 HTML 페이지(`/movies`) 자체가 브라우저/Edge 및 Cloudflare에 캐싱되던 심각한 문제를 해결했습니다.
* **조치**: 캐싱 키워드 필터에서 `'/movies'`를 제거하여 HTML 페이지 조회 시 항상 실시간 최신 목록이 반영되도록 조치했습니다. (비디오 스트리밍 자체는 여전히 확장자 매핑으로 강력 캐싱됩니다.)

## 3. 결과 및 검증 완료
* **테스트 결과**: 900MB 동영상 파일을 포털 본래 주소(`https://gallery.onnamu.kr/upload`)를 통해 성공적으로 업로드 및 병합 완료했습니다.
* **최종 반영**: 영화관 탭 목록에도 정상 노출되는 것을 확인하였으며, 관리 페이지 및 UI 버그(경고 감춤)도 모두 오동작 없이 성공적으로 마침을 검증했습니다.
