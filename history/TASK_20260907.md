# 2026-09-07 — 조회 통계에서 "사람이 화면에서 한 조회"를 갈라낸다

## 발단

> "실제 조회 페이지에서 조회를 한 사람이 있나? 있다면 사람이 들어와서 몇 건을
> 조회했냐 — 이거야. RDAP 조회 건수 중에 실제 '사람이 한 조회' 그 카운트인 거야?
> 부트스트랩을 통해서 조회한 게 아니고?"

되물음이 핵심을 짚었다. **아니었다.** 대시보드의 조회 숫자는 사람이 웹 조회
화면에서 누른 것과 남의 프로그램이 부트스트랩 주소를 곧장 부른 것이 **섞인 값**
이었다.

## 왜 섞여 있었나 — 표시가 기록 직전에 버려지고 있었다

우리 조회 화면과 남의 프로그램은 **같은 주소를 부른다.**

| 누가 | 실제로 부르는 주소 |
|---|---|
| 사람이 웹 조회 화면에서 | `bootstrap.rdap.kr/domain/xxx` **`?proxy=true`** |
| CLI·API·수집기가 | `bootstrap.rdap.kr/domain/xxx` |

차이는 `?proxy=true` 하나뿐이다(`client/js/rdap-client-view.js:140`). 그런데
접속 기록을 남기는 미들웨어가 `request.url.path`만 넘겨서 **물음표 뒤가 잘려
나갔다**(`main.py`). 조회 건수 누적 카운터(`manager.record_hit`)도 proxy 여부를
아예 인자로 받지 않는다. 그래서 두 요청이 기록에서 **글자 하나 다르지 않게**
남았고, 가를 방법이 원리적으로 없었다.

곁들여 확인한 것: 페이지별 방문 자료(`화면별`)는 `visit_view.py`가 **이미
계산해서 내려보내고 있었는데 대시보드가 그리지 않고 있었다.** 자료는 있고
화면만 없던 상태다.

## 고친 것

### ① 조회에 출처 표시를 남긴다 (`w` 칸 신설)

- `traffic_log.record(..., web=None)` — 넘겨받으면 `"w": 1/0`으로 적는다.
  **안 넘기면 칸 자체를 안 만든다.** 표시를 남기기 전의 옛 기록과 '표시가
  없는 요청'이 섞이면 안 되기 때문이다.
- `main.py`에 `_from_our_screen(request)` 신설 — `proxy` 값이 참일 때만 참.
  참으로 읽는 낱말(`1·t·true·y·yes·on`)을 **FastAPI가 참으로 읽는 것과 맞췄다.**
  안 맞추면 화면이 실제로 프록시를 탄 요청인데 기록만 0으로 남는다.
- **조회가 아닌 주소에는 표시를 안 남긴다.** 소개 화면·목록 파일에까지 0이
  붙으면 '우리 화면이 아니다'로 읽혀 뜻이 뒤집힌다. 판정은
  `traffic_stats.classify_path`(조회·자료·화면·훑기) 한 벌을 그대로 쓴다.

### ② 집계에 '어디서 왔나'를 더한다 (`traffic_stats.py`)

`조회.어디서 = {우리화면, 직접호출, 판정전}`. **`w` 칸이 아예 없는 줄은
'판정전'으로 따로 센다** — 0으로 보면 오늘 이전의 기록 전부가 '직접호출'로
몰려 숫자가 거짓말을 한다. 2026-08-28에 접속 프로그램 이름표를 넣을 때 '알 수
없음'을 따로 둔 것과 같은 이유다.

### ③ 화면마다 사람 수를 센다 (`visit_view.py`)

`화면별`이 조회 수만 세던 것을 **방문자(고유 표) 수와 함께** 세게 했다. 조회
수만으로는 한 사람이 여러 번 넘겨 본 것과 여러 사람이 한 번씩 들른 것이
구별되지 않는다.

### ④ 대시보드에 표 둘을 붙인다

- **조회가 어디서 왔나** — 우리 조회 화면 / 곧장 부른 요청 / 판정 전, 건수와 비율.
- **어느 화면을 봤나** — 화면마다 방문자 수와 장수.
  불러오는 중과 '쌓인 방문 없음'을 **다른 문구로** 갈랐다. 같으면 로딩이 '0건'
  으로 읽힌다.

## 쌍둥이 파일

형식이 같아야 하는 파일을 함께 고쳤다 — `traffic_log.py`(포털·RDAP)와
`visit_view.py`(포털·RDAP). 포털의 접속자 지도는 `화면별`에 늘어난 칸을
안 쓰므로 그대로 동작한다(3칸 표를 그리고 나머지는 무시).

## 확인

가짜 기록으로 집계를 돌려 셋을 실측했다.

| 확인한 것 | 결과 |
|---|---|
| 조회 5건(우리화면 2·직접 1·`w` 칸 없는 옛 기록 2) | `{우리화면: 2, 직접호출: 1, 판정전: 2}` — 옛 기록이 직접호출로 안 몰림 |
| 한 화면을 2명이 3장, 다른 화면을 1명이 1장 | 사람 수와 장수가 갈려 나옴 |
| `web=True/False/None`으로 기록 | `1` / `0` / **칸 없음** |
| 경로 판정 | `/domain/…`·`/ip/…`→조회, `/rdap-about-ko.html`→화면, `/dns.json`→자료, `/wp-login.php`→훑기 |

FastAPI가 이 환경에 없어 미들웨어를 통째로 띄운 확인은 못 했다 —
**배포 후 실제 화면에서 볼 것.**

## 남은 것 / 알아 둘 것

- **오늘부터 쌓이는 기록만 갈린다.** 오늘 이전 조회는 전부 '판정 전'이다.
  시간이 지나며 저절로 줄어든다.
- 누적 카운터(`manager.py`의 `stats.json`)는 손대지 않았다 — 시각이 없어
  기간을 나눌 수 없는 자료라 2026-08-28에 이미 대시보드가 안 읽도록 갈라 뒀다.
- `?proxy=true`는 **우리 화면만 붙인다는 약속**에 기대는 표시다. 남이 흉내 내
  붙이면 우리 화면 조회로 세어진다. 사람/기계 판정(User-Agent)과 함께 보면
  서로를 보완한다.
