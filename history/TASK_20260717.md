# TASK 2026-07-17 — NAMU 원격 MCP 서버 신규 서비스 배포

## 목적

웹 브라우저(claude.ai)에서 NAMU 기억(교훈)을 recall/record/search 할 수 있도록, namu-agent의 원격 Streamable HTTP MCP 서버를 미니PC에 상시 서비스로 배포한다. 배포 구조 결정은 NAMU 메모리 `onnamu-deploy` 기록(2026-07-17, hp 세션)을 따르며, 절차 근거는 namu-agent repo의 `docs/remote_mcp_guide.md`(namu-45)다.

## 결정 사항 (recall 기록 기준)

- **소스 전달**: GitHub 참조 빌드 — `https://github.com/onmiso-hash/namu-agent.git#v0.1.25` (버전 태그 고정, 로컬 폴더 복사 금지 → 사본 드리프트 방지)
- **라우팅**: `namu.onnamu.kr` → 컨테이너 8765 (Cloudflare named tunnel)
- **인증**: `NAMU_HTTP_PATH_SECRET` 시크릿 경로 단독 모드 (claude.ai Request headers UI가 베타 점진 롤아웃이라 헤더 인증 비의존)
- **Host 보호**: `NAMU_HTTP_ALLOWED_HOSTS=namu.onnamu.kr` (도메인을 미리 알므로 `*` 대신 지정 — 421 방지 + DNS rebinding 보호 유지)
- **기억 풀**: `NAMU_SYNC_REMOTE`로 기존 `~/.namu` 동기화 repo 재사용 → hp/samsung/웹 단일 풀
- **machine 구분**: 이미지 기본값 `NAMU_MACHINE=web` 그대로 사용

## 사용자 직접 작업 (시크릿·대시보드 — 세션에서 대행 불가)

1. **Windows 호스트 `gallery/.env`에 추가** (없으면 컨테이너가 기동 거부 → restart:always 크래시 루프):
   ```
   NAMU_SYNC_REMOTE=https://x-access-token:<PAT>@github.com/<user>/<sync-repo>.git
   NAMU_HTTP_PATH_SECRET=<임의의 긴 난수 문자열>
   ```
2. **Cloudflare Zero Trust 대시보드**: Public Hostname `namu.onnamu.kr` 추가 → 기존 `onnamu.kr`→5001 항목과 동일한 표기 방식으로 포트 8765 지정.

## 검증 절차 (배포 후)

1. `deploy.log`에서 `--- Deploy NAMU ---` 구간 빌드·기동 성공 확인.
2. 컨테이너 로그: clone→git identity→sync wiring→uvicorn 기동 순서 확인.
3. curl 스모크 (가이드 3-2절):
   ```bash
   curl -sS -X POST "https://namu.onnamu.kr/mcp/<secret>" \
     -H "Content-Type: application/json" \
     -H "Accept: application/json, text/event-stream" \
     -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"smoke","version":"0"}}}'
   ```
   정상 `result` 응답 + 오답 경로 404 + 421 미발생 확인.
4. claude.ai → Connectors → Add custom connector → `https://namu.onnamu.kr/mcp/<secret>` 등록(고정 주소라 최초 1회) → 대화에서 recall 실호출.

## 배포 중 발견된 갭 (2026-07-17 실측)

- **compose의 Windows git URL 컨텍스트 버그**: 미니PC(Windows Docker Desktop)의 `docker compose`가 `build.context`의 git URL을 로컬 경로로 잘못 해석(`CreateFile ...\namu\https:: syntax is incorrect`)해 빌드 실패. 우회책 — GitHub 참조 빌드를 deploy.yml의 `docker build`(BuildKit은 git URL 정상 처리)로 분리하고, compose는 `image:` 참조만 담당. PowerShell에서 URL의 `#`가 잘리지 않도록 작은따옴표 필수.
- **경로 혼동 주의**: 배포 호스트(미니PC)와 개발 머신(hp)의 Windows 사용자명이 동일(`onmis`)해 "어느 머신의 `C:\Users\onmis\project`인가" 혼선 발생 — 문서에 경로를 쓸 때 머신 명시 필요.
